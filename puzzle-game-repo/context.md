## 3. Technology Stack & Architectural Breakdown
- **Frontend Core**:
  - `HTML5`: Semantic elements (`main`, `header`, `section`, `button`, ARIA roles `grid`, `dialog`, `live`).
  - `CSS3`: Modern CSS Grid (`4x4` layout), Flexbox, CSS Custom Properties (`--bg-color`, `--card-bg`, `--tile-bg`, etc.), smooth transitions, responsive mobile-friendly viewport scaling.
  - `JavaScript (ES6+)`: Encapsulated in an IIFE to avoid global scope pollution. State management using an in-memory 1D array of 16 elements (`board = [1..15, 0]`, where `0` designates the blank slot).
- **Game Mechanics**:
  - **Grid Size**: 4x4 (16 cells total: 15 numbered tiles, 1 empty space).
  - **Tile Swapping**: Adjacency check using Manhattan distance `|r1 - r2| + |c1 - c2| === 1`.
  - **Solvability Guarantee**: Generated by applying consecutive valid random walks from the solved board state (`getSolvedState()`), mathematically guaranteeing a solvable permutation.
  - **Controls**:
    - Pointer clicks and taps on tiles adjacent to the empty slot.
    - Keyboard handlers: `ArrowUp`, `ArrowDown`, `ArrowLeft`, `ArrowRight`, and `W`, `A`, `S`, `D`.
  - **Game Timing & Scoring**:
    - Move Counter incremented on every legal move.
    - Elapsed stopwatch started upon the first legal move and stopped when the solved permutation is reached.
  - **Win Condition**: Detected when tiles array indices 0 to 14 contain `1` to `15` and index 15 contains `0`. Displays modal overlay with elapsed time and total moves.

## 4. How the Game Runs Locally
- **Direct Browser Execution**: Can be opened directly in any modern browser (`Chrome`, `Firefox`, `Safari`, `Edge`) via `file:///path/to/slide-puzzle.html` without requiring compilation, bundling, or a local server.
- **Local Web Server**:
  - Python: `python3 -m http.server 8000`
  - Node / npx: `npx serve .` or `npx http-server`
  - Vite dev server: port 3000

## 5. Existing Tests, Dependencies, and Potential Bugs
- **Existing Dependencies**: The core game in `slide-puzzle.html` intentionally has zero external runtime dependencies.
- **Automated Tests**: No pre-existing test suite was present in the baseline repository.
- **Identified Baseline Gaps / Bugs**:
  1. **Missing Pause Functionality**: Once started, the timer runs continuously; players cannot pause during interruptions.
  2. **No Input Blocking on Inactive State**: While `isWon` stops interaction, there is no pause-state guard for keyboard and click inputs.
  3. **Timer Drift**: `setInterval` with 1-second ticks is used; when pausing and resuming, exact elapsed time must be preserved without losing seconds or drifting.
